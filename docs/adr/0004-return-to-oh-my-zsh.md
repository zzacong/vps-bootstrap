# 0004-return-to-oh-my-zsh

Supersedes [0003-antidote-zsh-plugin-manager](./0003-antidote-zsh-plugin-manager.md). The bootstrap scripts install oh-my-zsh again: the official curl installer (`--unattended`) on both flows, with the four plugins oh-my-zsh doesn't bundle (zsh-completions, zsh-autosuggestions, zsh-you-should-use, fast-syntax-highlighting) cloned into `~/.oh-my-zsh/custom/plugins`. zoxide is installed too — brew on a Mac, its official curl script on a VPS.

ADR-0003 switched to antidote because oh-my-zsh was "a framework: a curl installer that wrote its own `.zshrc`, owned a `custom/plugins` directory the bootstrap scripts had to clone into, and shipped a bundled theme/prompt machinery we never used." That diagnosis was correct, but the practical outcome of the switch was more trouble than it saved: antidote's plugin ownership lived in a second file (`~/.zsh_plugins.txt`) in the dotfiles repo, the `.zshrc` had to source antidote and call `antidote load` before any plugin existed on a fresh box, and the bootstrap scripts gained a second install mechanism (git clone on the VPS, a brew formula on the Mac) for a plugin manager that itself only clones other plugins. Every box and every toolchain converged on oh-my-zsh's `plugins=(...)` array in the dotfiles; going back restores one install mechanism and one place to read the plugin list. The plugins that need manual clones are still cloned by the scripts, so a fresh box boots to a working prompt without a first-login load step.
